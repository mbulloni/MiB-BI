# CLAUDE.md — MiB-BI

Educational Power BI Desktop clone for Linux. Electron 44 + React 19 + TypeScript + Vite 8, DuckDB (`@duckdb/node-api`) as engine, ECharts for charts, zustand for state. UI text is Italian, mirroring Power BI's Italian localization.

## Commands
- `npm run dev` — Vite (5173) + Electron. `npm start` — production build + Electron. `npm run typecheck`.
- Electron's binary download may be blocked by npm 12 install-script policy: `node node_modules/electron/install.js`.
- Visual smoke test: `MIBBI_SHOT=out.png MIBBI_SCRIPT=steps.js npx electron . --no-sandbox` (store as `window.__mibbi`, query builder as `window.__mibbiQuery`, Power Query compiler as `window.__mibbiPQ`, DAX as `window.__mibbiDax`; a returned value is printed as `SCRIPT_RESULT`; `window.__mibbiRun(visual)` = runVisualQuery, `window.__mibbiCalc(visual)` = the same with visual calculations and custom totals; `MIBBI_PBIT_OUT`/`MIBBI_PBIP_OUT`/`MIBBI_PDF_OUT`/`MIBBI_SAVE_PATH`/`MIBBI_OPEN_PATH` skip the file dialogs).

## Layout
- `electron/` (CommonJS): `main.cjs` window/IPC/dialogs, `db.cjs` DuckDB, `sample.cjs` Financials generator, `preload.cjs` → `window.api`.
- `src/store.ts` — all report state + actions; mutations go through `mut()` (undo snapshot of `report`).
- `src/query.ts` — visual → SQL. `core()` builds per-measure-table subqueries over a join tree (`joinTree`, `edgesFrom` encode Power BI filter direction), `finalize()` adds VARCHAR display cols (`cN`) next to raw keys (`k_cN`, used for sorting). Fan-out hops dedupe on `t0.rowid`.
- `src/components/ModelView.tsx` (diagram), `Relationships.tsx` (manage/edit dialogs, `activationConflict`).
- `src/visuals/catalog.ts` — visual types and their wells. `ChartVisual.tsx` (ECharts), `Others.tsx` (card/table/matrix/slicer/textbox).
- `src/panes/` — Filters, Visualizations (build + format), Data.
- `src/visuals/visualCalc.ts` — visual calculations: `stripCalcs` (the query never sees them), `CalcEngine` (JS interpreter on the visual matrix: levels = kept row/column dims, window functions, COLLAPSE/EXPAND), `customTotals`. Applied in `useVisualData` (`withCalcs`); extra level queries are the visual with fewer grouping fields (`levelVisual`). Edit mode: `components/VisualCalcEditor.tsx` (`store.calcEdit`).
- DAX UDFs: `parse.ts` `fnDef`/`parseFunction`, `engine.ts` `expandUdf` (AST rewrite: EXPR params substituted, VAL params bound as VARs with unique names). Calendars: `engine.ts` `calendarTi` (index of the calendar table: `f` fine order, `o_<unit>` period number, `p_<unit>` position), `calendarKey`; dialog `components/CalendarDialog.tsx`.
- Power Query (`src/pq/`): `Step` union in `types.ts`, stored on `TableMeta.steps`. `compile.ts` → SQL (one CTE per step, hidden `__r` ordinal; refs/merge/append inlined as subqueries, so `compileQuery` needs all query defs), `m.ts` → M (formula bar, Editor avanzato, `.pbit` via `pbit.ts#queryM`), `mexpr.ts` translates custom-column M formulas to SQL, `steps.ts` step names ("Rimosse colonne1"…). Every table load goes through `store.loadTable` → `api.materialize(name, sql)`. Editor state is `store.pq` (draft copies of all queries; `pqApply` = Chiudi e applica, reloads changed queries + dependents, renames tables in the report). UI: `components/PowerQuery.tsx` + `PowerQueryDialogs.tsx`.
- Files: `.mibx` = zip (`report.json` + `data/<i>.parquet`, written by main `file:save`, unpacked to `~/.config/mib-bi/mibx-data/<hash>` on open; plain-JSON v1 still opens). `.pbip`: `electron/pbip.cjs` (TMSL/TMDL + PBIR/legacy report → same shape as read_pbix.py output), `src/pbix/pbir.ts` converts PBIR to legacy Layout for `parseLayout` and back (`layoutToPbir`, schema versions in `V`: visualContainer 2.7.0, page 2.1.0, report 3.2.0…); `src/pbix/tmdl.ts#tmslToTmdl` writes TMDL (expressions two tabs deeper than their line, as Desktop); `buildPbipParts(report, tables, {pbir, tmdl})` from `options.ts` (default both); `pbip.cjs#write` removes old definitions first. Validate PBIR output with Microsoft's schemas (github.com/microsoft/json-schemas, fabric/item/report) + ajv. Themes: `src/themes.ts` mutates the shared `PALETTE` (store subscription on `report.theme`). PDF: `store.exportPdf` renders `.print-root` (all pages, `VisualStatic`) and main `pdf:print` calls `printToPDF` (print CSS in styles.css).
- Database sources: `electron/connect.cjs` (ATTACH via DuckDB mysql/postgres/sqlite extensions, credentials encrypted with safeStorage in userData, keyed by `keyOf()`); `TableMeta.source.db`; the PQ compiler gets sources through `api.sourceExpr(source)`. UI `components/DatabaseDialog.tsx`.
- Publish to the Power BI service: `electron/powerbi.cjs` (browser PKCE login, device code fallback, built-in or user Entra app, profiles in `userData/powerbi.json` = `{ active, profiles: [{ id, name, clientId, tenant, refresh, account, lastWorkspace, … }] }`, `loadCfg`/`saveCfg` act on the active profile, old flat file migrated to profile "Predefinito"; refresh token via safeStorage; `publishPush` = push dataset + thin .pbix import + Rebind, Fabric Create Report fallback; `publishFabric` = Fabric item definitions model.bim/report.json, local data embedded as deflate+base64 JSON in M, then refresh). Builders in `pbit.ts` (`buildPushSchema`, `buildThinPbixParts`, `buildReportParts`, `buildFabricModel`), UI `components/PublishDialog.tsx`. `MIBBI_PBI_LOGIN`/`MIBBI_PBI_API`/`MIBBI_PBI_FABRIC` redirect endpoints to a mock server, `MIBBI_PBI_THIN_OUT` dumps the thin .pbix.
- Power BI files: `electron/pbix/read_pbix.py` (run by main via `.venv-pbix` python or `MIBBI_PYTHON`; `npm run setup:pbix`) writes `model.json` + Parquet into `~/.config/mib-bi/pbix-cache/<hash>`. `src/pbix/layout.ts` maps Report/Layout ↔ MiB-BI pages, `src/pbix/pbit.ts` builds .pbit parts (UTF-16LE, no BOM; jszip in main), DAX measures are `FieldRef.agg === 'measure'`.
- DAX (`src/dax/`): `parse.ts` (lexer/parser, VAR, DEFINE/EVALUATE), `engine.ts` (`Compiler`: filter context = list of `Filt` predicates per table; aggregations are correlated subqueries; other tables' filters reach a table via `semi()` chains along `edgesFrom`; `calculate()` = transition + ALL removals + overriding filter args; table filters use expanded tables via `tableFilters()`; `once()`/`framed()` bind repeated values in derived tables to avoid exponential SQL). `query.ts#buildVisualQuery` keeps groups/plain aggregations and adds each DAX measure as `measureSql(..., groups ref g.k_cN)`. Calculated columns (`TableMeta.calcColumns`) and tables (`source.dax`) are applied by `store.finalizeModel()` after loads; editing via `store.daxEdit` + `components/DaxBar.tsx`; `components/DaxQueryView.tsx` = Vista query DAX (`daxQuerySql`).

- Power BI formatting fidelity: `Visual.style` keeps the imported `objects`/`vcObjects` (+ `pbiType`, and the whole `singleVisual` as `raw` for visuals MiB-BI cannot render). Renderers read it with `visuals/pbistyle.ts#sp(v, obj, prop, state?)` (plain or `{id:'default'}` entries, then theme `visualStyles`), colors via `decode` (Literal, ThemeDataColor ColorId 0=bg 1=fg 2..=dataColors, Percent tint/shade), font sizes in pt (`pt()`). Title/background/border also map to `VisualFormat` (editable). `buildLayout` starts from `style` and overwrites only MiB-BI-managed props. Pages keep size (`width/height`), `backgroundColor/Transparency/Fit`, `wallpaper` (outspace), `hidden`, `pbiName` (section name, target of navigation buttons). Buttons/shapes: `visuals/Shapes.tsx` (Ctrl+click runs page navigation/back/web URL). Conditional formatting: `visuals/condfmt.ts`, `VisualFormat.cf` keyed by `fieldKey()`.

- Maps: `visuals/MapVisual.tsx` (ECharts geo, Mercator projection, `boundingCoords` fit; filled-map colors through `geo.regions` because a map series bound to a geo ignores item styles; location+legend = custom pie series). Offline geocoding `geo/geocode.ts`: layers in `src/geo/*.json` (TopoJSON object `f`, props `n` name, `k` normalized aliases, `c` inner point; loaded lazily with `?raw`), best layer = data category hint (`TableMeta.dataCategory`, from the model or Vista dati › Strumenti colonna = `store.setColumnProps`), else column-name hint, then most matches. Layers: world, continents, admin1 (every country, `p` = ISO2), US states, IT regions/provinces/municipalities; points: cities, postal (GeoNames, shared codes resolved by the country matching most values, prefix fallback "SW1A 1AA" → SW1A). Regenerate with `scripts/build-geo.mjs` (`GEO_ONLY=` for single layers).

- AI visuals (`visuals/AiVisuals.tsx`) run their own queries through `useVisualData.ts#runVisualQuery` (synthetic table/card visuals with the same id, page filters and extra filters); `buildVisualQuery` returns null for them. Tree path in `Visual.tree`, key influencers state in `Visual.ki` (`tab: 'segments'` = Segmenti principali: one `pythonVisual`-shaped query per factor combination, greedy variance-reduction tree depth ≤ 3 in `grow()`, leaves kept when z ≥ 1.96 vs the rest). ## Gotchas
- pandas NaN must never reach model.json (JS JSON.parse fails): `json.dump(allow_nan=False)`.
- Old Report/Layout files keep visual geometry only in `config.layouts[0].position`.
- pbixray's public API lacks SortByColumn/measure FormatString: read via `model._metadata.source._db` (metadata.sqlitedb).
- Driver dates: the CSV bridge writes UTC (`toISOString`); mssql runs with `useUTC: true`, node-oracledb returns zone-less DATE/TIMESTAMP as local time, so the Oracle adapter shifts them by the offset before writing.
- `getRowObjectsJson()` returns BIGINT/HUGEINT as strings (e.g. `GROUPING()` → `"0"`): wrap with `Number()`.
- Relationships live in `report.relationships` (undo + saved in .mibx); `from` is always the many side. Old .mibx files get `relationships`/`modelLayout` defaulted in `open()`.
- A column/measure SQL value referenced twice must go through `Compiler.once()` (or VAR/measure sharing): DuckDB macros and plain string reuse duplicate subqueries.
- Visual calc FieldRefs (`agg: 'visualCalc'`, `table: ''`) live in the wells: code iterating `v.fields` for model fields must skip them (filters pane, layout `entities`, changeVisualType). `format.sortBy` indexes the flat well list, `stripCalcs` remaps it.
- Visual calcs reference fields by their well label (`fieldLabel`, e.g. "Somma di Sales"); export writes it as `nativeQueryRef`, import maps Power BI's `nativeQueryRef` back to MiB-BI labels.
- `Omit<Step,'id'>` does not distribute over the union: use `NewStep` from `types.ts`.
- DuckDB `UNPIVOT` refuses mixed column types: the step carries `cast: true` (decided from the schema when created) to cast to VARCHAR first.
- `useVisualData` takes filters from the page that contains the visual (not the active page): required by PDF export.
- Page is 1280×720 logical px, scaled with CSS transform; react-rnd gets `scale`.
